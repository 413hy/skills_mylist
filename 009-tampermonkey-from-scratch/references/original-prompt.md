# 原始 Prompt

> 这是从旧合集迁移过来的原始内容，仅用于保留完整语义。执行时优先遵守 SKILL.md 和 eferences/workflow.md 中的优化后流程。

## 原始 Prompt

### Prompt
```text
【变量区】
- `<SCRIPT_GOAL>` = 这次油猴脚本要实现的目标（包含：根据用户提供的补充要求，动态调整脚本架构与功能的目标）
- `<TARGET_CONTEXT>` = 目标网站 / 页面 / 触发场景 / 关键页面特征
- `<CORE_FLOW>` = 需要自动执行的核心流程（按步骤列出）
- `<SPECIAL_REQUIREMENTS>` = （可留空；例如 debug 面板、开始/暂停按钮、重试策略、仅特定 URL 生效等；你需要据此调整脚本架构与功能）

【任务】
我要从零开始创建一个 Tampermonkey（油猴）脚本，请你担任我的脚本设计与开发助手。

本次脚本目标：
`<SCRIPT_GOAL>`
（你必须在整个设计与实现过程中，持续对齐该目标，并根据我后续提供或补充的 `<SPECIAL_REQUIREMENTS>` 对脚本架构与功能做相应调整，而不是固定沿用默认方案。）

目标上下文：
`<TARGET_CONTEXT>`

核心流程：
`<CORE_FLOW>`

补充要求：
`<SPECIAL_REQUIREMENTS>`
（这些补充要求可能会影响架构选型、模块拆分、交互方式、失败处理、稳定性策略与风控策略；你需要在确认阶段主动澄清其优先级，并在最终方案中逐条落实或说明取舍。）

在你给出方案、代码或实现步骤之前，请严格遵守以下沟通规则：
1. 先向我提问，不要直接给方案或完整代码。
2. 一次只问一个问题。
3. 根据我的回答继续追问，优先确认最关键、最容易影响实现的问题。
4. 只有当你对我的真实需求、页面环境、执行目标、失败处理方式、稳定性要求和风险点有至少 95% 把握时，才开始输出方案。
5. 在此之前，不要直接输出完整代码。
6. 如果我给的信息不完整，请通过提问逐步补齐，不要自行脑补关键前提。
7. 如果你发现某些实现方式可能脆弱、容易失效或有风控风险，请优先提问确认，不要直接默认采用。
8. 若我在对话中新增或修改补充要求（`<SPECIAL_REQUIREMENTS>`），你需要优先通过提问确认其影响范围与优先级，并在后续设计中据此调整脚本架构与功能。

请你在提问阶段，优先逐步确认以下方面：
- 这个脚本是完全自动、半自动，还是人工确认后继续
- 是否允许使用轮询、MutationObserver、定时器重试
- 页面是否可能改版，是否需要更稳健的选择器策略
- 关键元素应通过什么方式识别（XPath、CSS、文本、URL、属性、组合条件）
- 某一步失败后是停止、重试、跳过，还是回滚
- 是否需要开始 / 暂停 / 继续 / 停止按钮
- 是否需要右下角 debug 面板
- debug 面板需要显示哪些状态、日志、错误、步骤进度
- 是否只在特定 URL / 特定页面生效
- 是否有账号安全、访问频率、风控、人机验证、权限限制等顾虑
- 补充要求（`<SPECIAL_REQUIREMENTS>`）中哪些是“必须实现”、哪些是“可选增强”、哪些可以“用替代方案实现”；如存在冲突，优先级如何

当你确认完问题后，再按以下结构输出：
1. 需求确认总结（包含：补充要求的清单、优先级、以及它们如何影响脚本架构与功能的结论）
2. 风险点与假设
3. 脚本架构设计（需明确说明：如何为补充要求预留扩展点/模块，以便后续调整）
4. 完整油猴脚本
5. 关键函数说明
6. 调试方式
7. 常见故障排查

代码要求：
- 可直接保存为 `.user.js`
- 注释清晰
- 结构清楚，便于后续维护
- 尽量避免脆弱实现
- 每一步都能显示当前状态
- 出错时要有明确日志
- 如果需要 debug 面板，请放在页面右下角
- 如果流程依赖人工完成某一步（例如验证码、人机验证、手动确认），脚本必须能够等待该条件满足后再继续
- 必须能够根据我提供或新增的补充要求（`<SPECIAL_REQUIREMENTS>`）调整或扩展实现，并在最终输出中明确对应关系（“哪条补充要求 -> 代码中在哪里实现/如何实现”）

输出方式要求：
- 在提问阶段，每次只问一个问题
- 不要一次抛出多个问题
- 不要过早开始写代码
- 当信息足够后，再一次性输出完整方案与代码
```

### 变量
- `<SCRIPT_GOAL>`：这次油猴脚本要实现的目标
- `<TARGET_CONTEXT>`：目标网站 / 页面 / 触发场景 / 关键页面特征
- `<CORE_FLOW>`：需要自动执行的核心流程（按步骤列出）
- `<SPECIAL_REQUIREMENTS>`：可选补充要求
